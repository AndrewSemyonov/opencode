# Отчёт: картофельное пюре для 5-11 класса в Салехарде

Этот skill предназначен для одного демонстрационного отчёта и отвечает именно на вопрос:

> Сколько по нормативу должно быть выдано картофельного пюре для 5-11 класса в Салехарде?

Не превращай этот skill в универсальный генератор отчётов. Для других отчётов будут отдельные skills.

Если пользователь просит сформировать отчёт, сделать расчёт нормы питания, спрашивает про картофельное пюре, 5-11 класс или Салехард, используй этот demo-сценарий и сформируй отчёт по вопросу выше.

## Цель

Найти в data sources проекта норматив выдачи картофельного пюре для обучающихся 5-11 классов в Салехарде, проверить единицы измерения через Python и сохранить визуальный **MDX**-отчёт в `reports/`.

Отчёт должен быть привязан к чату, в котором он сгенерирован: в самое начало `.mdx`-файла добавляется служебный frontmatter с `sessionId`. По этому полю интерфейс открывает исходный чат при открытии отчёта из файла. Frontmatter не отображается во вьювере — он нужен только для связи «отчёт → чат».

Файл отчёта должен называться:

`reports/report-YYYY-MM-DD-HH:mm.mdx`

Используй текущие локальные дату и время для `YYYY-MM-DD-HH:mm`.

Если файл с таким именем уже существует, добавь короткий числовой суффикс перед `.mdx`, например:

`reports/report-YYYY-MM-DD-HH:mm-2.mdx`

Расширение обязательно `.mdx` — только такие файлы рендерятся вьювером с графиками и компонентами.

## Фиксированные параметры отчёта

Всегда используй эти параметры:

- **Город/территория**: Салехард.
- **Блюдо**: картофельное пюре.
- **Группа**: 5-11 класс.
- **Искомая величина**: норматив выдачи на одного обучающегося.
- **Единица результата**: граммы на одного обучающегося.

Если пользователь указал количество обучающихся, дополнительно посчитай суммарную выдачу в граммах и килограммах. Если количество не указано, не выдумывай его и считай только норму на одного обучающегося.

## Обязательный порядок работы

### 1. Зафиксируй вопрос

Даже если пользователь сформулировал запрос коротко, в отчёте используй полный вопрос:

`Сколько по нормативу должно быть выдано картофельного пюре для 5-11 класса в Салехарде?`

Если пользователь добавил численность, отрази её отдельно в расчёте, но не меняй базовый вопрос.

### 2. Найди data sources

Сначала проверь наличие локальных источников данных в проекте:

- `./data-sources/`;
- `./data/`;
- `./datasets/`;
- `./sources/`;
- `./reports/`;
- файлы в корне и подпапках с расширениями `.md`, `.txt`, `.csv`, `.tsv`, `.xlsx`, `.xls`, `.json`, `.yaml`, `.yml`, `.sqlite`, `.db`;
- профили БД, созданные skill `db-connect`: `./data-sources/{name}/README.md` и `./data-sources/{name}/credentials.yaml`.

Ищи по русским и возможным техническим ключам:

- `картофельное пюре`, `картофельное`, `пюре`;
- `5-11`, `5–11`, `5 — 11`, `5 класс`, `11 класс`, `средняя`, `старшая`;
- `Салехард`, `ЯНАО`, `Ямало-Ненецкий`;
- `норматив`, `выход`, `масса порции`, `порция`, `грамм`, `г`, `нетто`, `примерное меню`, `школьное питание`.

Если `./data-sources/{name}/credentials.yaml` описывает SQL-источник, подключись к нему в режиме чтения и найди релевантные таблицы. Используй только безопасные SELECT-запросы. Не изменяй данные.

### 3. Извлеки норматив

Найди запись, которая одновременно соответствует:

- блюду `картофельное пюре`;
- группе `5-11 класс` или эквивалентной возрастной группе;
- Салехарду или нормативному источнику, явно применимому к Салехарду;
- массе/выходу порции в граммах.

Для каждого релевантного источника зафиксируй:

- путь к файлу или имя SQL data source;
- название таблицы/листа/раздела;
- найденную строку или запись;
- нормативное значение и единицу измерения;
- область применимости;
- дату, версию или период действия документа, если они есть.

Если найдено несколько разных значений, не выбирай молча одно. Сравни источники в отчёте и объясни, какой источник считаешь основным и почему.

Если релевантных data sources нет или данных недостаточно, всё равно создай отчёт, но явно напиши, что расчёт невозможен без источника нормативов. Не используй интернет и не подставляй норматив из памяти, если пользователь прямо не попросил искать снаружи.

### 4. Посчитай через Python

Все арифметические расчёты выполняй через Python, даже если расчёт простой.

Минимальный расчёт:


```text
норматив_на_человека_г = найденное_значение
норматив_на_человека_кг = норматив_на_человека_г / 1000
```



Если пользователь указал количество обучающихся:


```text
количество_обучающихся = N
итого_г = норматив_на_человека_г * количество_обучающихся
итого_кг = итого_г / 1000
```



В отчёте покажи либо сам короткий Python-фрагмент, либо проверяемый текстовый вывод Python с исходными числами и результатом.

**Важно:** все числа, которые попадут в графики и KPI отчёта, должны быть результатом этого Python-расчёта. Не пересчитывай в уме и не округляй "на глаз".

### 5. Получи ID сессии

Перед сохранением отчёта вызови инструмент `session-id`. Он возвращает идентификатор текущей сессии (чата).

- Используй ровно ту строку, которую вернул инструмент, без изменений, кавычек и пробелов.
- Это значение пойдёт в поле `sessionId` служебного frontmatter в самом начале `.mdx`-файла.
- Если по какой-то причине инструмент недоступен и ID получить нельзя — не выдумывай его: оставь поле пустым (`sessionId:`) и продолжи формирование отчёта.

### 6. Сформируй отчёт

Создай `reports/`, если директории нет. Сгенерируй ровно один `.mdx` файл за запуск.

Файл **обязан начинаться** с frontmatter-блока с `sessionId` (см. «Структура отчёта»). Frontmatter идёт самой первой строкой файла, до заголовка `#`.

## Формат отчёта (MDX)

Отчёт — это `.mdx` файл. Он начинается со служебного frontmatter-блока, а дальше можно свободно сочетать обычный Markdown (заголовки, абзацы, списки, таблицы, fenced-блоки кода) и компоненты из белого списка ниже. Вьювер рендерит контент как визуальный отчёт, frontmatter при этом не показывается.

Жёсткие правила:

- Файл начинается с frontmatter: первая строка — ровно `---`, затем строки вида `ключ: значение`, затем закрывающая строка `---`. Frontmatter должен содержать `sessionId` со значением из инструмента `session-id`.
- Используй **только** компоненты из списка ниже, имена строго с учётом регистра. Любой другой тег не отрендерится.
- **Все пропсы — только статические литералы**: числа, строки, массивы, объекты, `true/false/null`. Нельзя переменные, вычисления, вызовы функций, тернарники, JSX-выражения с логикой. Числа в графики вписывай прямо в разметку, беря их из вывода Python-расчёта.
- Цвета подставляются автоматически из палитры. Вручную `backgroundColor` / `borderColor` не указывай без необходимости.
- Не выдумывай данные ради красивого графика. Если для визуализации нет реальных чисел из источника — не строй график.
- Текст внутри компонентов и подписи (`label`, `title`, оси) — на русском.

### Доступные компоненты

Графики. Все принимают `data`, опционально `options` (нативный chart.js-конфиг, мерджится поверх дефолтов), `height` (px, по умолчанию 320), `width`, `class`. Категориальные графики: `data={{ labels: string[], datasets: [{ label, data: number[] }] }}`. Для scatter/bubble: `data={{ datasets: [{ data: [{x,y}] | [{x,y,r}] }] }}`.

- `<LineChart>` — линейный.
  ```mdx
  <LineChart data={{ labels: ["Янв","Фев","Мар"], datasets: [{ label: "Выдача, г", data: [120, 145, 162] }] }} />
  ```
- `<AreaChart>` — линейный с заливкой (как LineChart, авто `fill` + сглаживание).
  ```mdx
  <AreaChart data={{ labels: ["Н1","Н2","Н3"], datasets: [{ label: "Порции", data: [320, 410, 380] }] }} />
  ```
- `<BarChart>` — столбчатый.
  ```mdx
  <BarChart data={{ labels: ["1-4 кл","5-11 кл"], datasets: [{ label: "Норма, г", data: [150, 200] }] }} />
  ```
- `<StackedBarChart>` — стек-бар (несколько datasets складываются).
  ```mdx
  <StackedBarChart data={{ labels: ["Пн","Вт"], datasets: [{ label: "Гарнир", data: [200, 210] }, { label: "Соус", data: [20, 25] }] }} />
  ```
- `<PieChart>` — круговая.
  ```mdx
  <PieChart data={{ labels: ["Картофель","Молоко","Масло"], datasets: [{ data: [70, 20, 10] }] }} />
  ```
- `<DonutChart>` — кольцо (как Pie, с прорезанным центром).
  ```mdx
  <DonutChart data={{ labels: ["Белки","Жиры","Углеводы"], datasets: [{ data: [12, 30, 58] }] }} />
  ```
- `<RadarChart>` — радар. Шкала по умолчанию 0…10; для бо́льших значений передай `options={{ scales: { r: { suggestedMax: 100 } } }}`.
  ```mdx
  <RadarChart data={{ labels: ["Калории","Белки","Жиры","Углеводы"], datasets: [{ label: "Порция", data: [8, 6, 7, 9] }] }} />
  ```
- `<ScatterChart>` — точечный, `data` каждого dataset — массив `{x, y}`.
  ```mdx
  <ScatterChart data={{ datasets: [{ label: "Замеры", data: [{x:1,y:2},{x:2,y:3},{x:3,y:5}] }] }} />
  ```
- `<BubbleChart>` — пузырьковый, `{x, y, r}` (r — радиус в px).
  ```mdx
  <BubbleChart data={{ datasets: [{ label: "Школы", data: [{x:10,y:20,r:8},{x:20,y:35,r:14}] }] }} />
  ```
- `<PolarAreaChart>` — полярная.
  ```mdx
  <PolarAreaChart data={{ labels: ["Пн","Вт","Ср"], datasets: [{ data: [11, 6, 8] }] }} />
  ```
- `<GaugeChart>` — спидометр. Пропсы: `value` (обяз.), `min` (0), `max` (100), `label`, `height` (200).
  ```mdx
  <GaugeChart value={200} max={300} label="Норма, г/чел" />
  ```
- `<Chart>` — общая обёртка для экзотических типов chart.js. Пропсы: `type`, `data`, `options`.
  ```mdx
  <Chart type="line" data={{ labels: ["Q1","Q2"], datasets: [{ label: "Выдача", data: [120, 180] }] }} />
  ```

Отчётные UI-компоненты:

- `<KPI>` — крупная цифра с дельтой. Пропсы: `title?`, `value` (обяз.), `unit?`, `delta?`, `deltaKind?` (`"positive"|"negative"|"neutral"`), `hint?`.
  ```mdx
  <KPI title="Норма на обучающегося" value={200} unit="г" hint="5-11 класс, Салехард" />
  ```
- `<Stat>` — компактный KPI, те же пропсы. Для строки из нескольких показателей.
  ```mdx
  <Stat title="На 1 чел" value="200" unit="г" />
  ```
- `<Callout>` — цветной блок. Пропсы: `type` (`"info"|"warning"|"success"|"danger"`, по умолчанию `info`), `title?`, тело — markdown.
  ```mdx
  <Callout type="warning" title="Конфликт источников">
  Два документа дают разные значения нормы — см. таблицу ниже.
  </Callout>
  ```
- `<Grid>` — адаптивная сетка. Пропсы: `cols` (число → `repeat(N,1fr)`, или строка raw CSS; по умолчанию 2), `gap` (число px или строка; по умолчанию `"12px"`).
  ```mdx
  <Grid cols={2}>
    <KPI title="На 1 чел" value={200} unit="г" />
    <KPI title="Итого" value="60" unit="кг" />
  </Grid>
  ```
- `<Card>` — карточка-контейнер. Пропсы: `title?`, `subtitle?`, тело — markdown/компоненты.
  ```mdx
  <Card title="Состав порции" subtitle="по нормативу">
    <PieChart data={{ labels: ["Картофель","Молоко","Масло"], datasets: [{ data: [70, 20, 10] }] }} />
  </Card>
  ```
